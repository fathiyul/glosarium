Learning how to learn means using methods that make new knowledge stick, rather than relying on how it feels to read something. Reading an explanation and nodding along feels like learning, but it often isn't. The test is whether you can use the idea without looking at the explanation.

Three habits help most:

- **Practice with feedback.** Solve a problem, check the result, then try a variation. Repeating the same tutorial steps gives little feedback.
- **Review over time.** Revisit an idea a few days later, and again after a longer gap. Spaced review works better than cramming the same material in one sitting.
- **Build something.** A small project forces you to make decisions that a reading list never does, and it shows you where your understanding is thin.

```
Day 1: learn how database indexes work, write a note in your own words
Day 3: explain it aloud without the note
Day 10: use it on a real slow query and check the plan
```

The classic mistake is collecting resources instead of using them. A long saved list feels productive, but it doesn't change what you can do. Pick one thing, use it on something real, and come back to it. [Tutorial hell](/t/tutorial-hell) is the usual way this goes wrong.
