Return rate: units returned ÷ units sold in a window (you can count orders or value instead — pick one and label it):

```text
10,000 units shipped, 1,200 returned = 12%
```

The level only means anything in context — fashion runs structurally higher (double digits are routine in many markets), electronics lower — and the **reason split matters more than the headline**: "wrong size" is a listing problem (size charts), "not as described" is a trust problem (photos that oversell), "damaged in transit" is a logistics conversation. Tag reasons at intake and the dashboard becomes a work queue instead of a guilt slide.

A return is not a cancelled sale; it is a second cost cycle:

```text
cost per return = reverse shipping + handling + restocking
                  + open-box value loss + refund float time
                  + customer-service effort
```

which is why a 25%-return category can be unprofitable under a healthy [gross margin](/t/gross-margin) headline, and why founders modeling PMF economics should price expected returns into cohorts before the first big campaign — a flash-sale cohort that returns 30% of what it "bought" was a discount you paid twice.

The COD note for Indonesian stores: doorstep rejection is a return wearing different clothes. Report rejection rate by region, courier and payment method ([cash-on-delivery](/t/cash-on-delivery)) — "conversion is fine, fulfillment is where we lose them" is this category's most common misread.

The counterintuitive part: returns policies are also a [conversion](/t/conversion-rate) lever. A generous policy on high-consideration items often lifts sales enough that net profit improves despite a higher rate — test it (and watch the [repeat behavior](/t/repeat-purchase-rate) of easy-return customers) instead of reflexively tightening. When not to optimize: tiny volumes (anecdote territory) and categories where the try-on model *is* the product — that is a cost structure, not a leak.
